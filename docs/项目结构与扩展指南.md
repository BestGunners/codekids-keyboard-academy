# 项目结构与扩展指南

本文档说明 CodeKids Keyboard Academy 的代码组织方式，以及如何在此基础上继续增加课程内容与新的关卡类型。

## 一、目录结构

```
src/
├─ components/          展示层：只负责渲染与交互，不放业务规则
│  ├─ common/           通用 UI：Button / Card / ProgressBar / StarRating / StatChip / Modal
│  ├─ layout/           AppShell / KidHeader / RequireChild（登录守卫）
│  ├─ keyboard/         VirtualKeyboard / HandGuide / FingerHint（键盘与手指提示）
│  ├─ typing/           TextStream / TypingStatsPanel / TypingStage / TypingResult / WarningBanner / WeakKeyReport
│  └─ map/              StageIsland / LessonNode / MapSummary（学习地图）
├─ pages/               路由页面：HomePage / LoginPage / MapPage / TypingPage
├─ engine/              纯逻辑层：不依赖 React，可单独做单元测试
│  ├─ keyMap.ts         键盘布局、键位 → 手指映射、Shift 规则（唯一事实来源）
│  ├─ typingEngine.ts   打字会话状态机、统计、星级、提示阶梯
│  ├─ attemptAggregator.ts  跨题目汇总本关成绩
│  └─ progress.ts       解锁规则、阶段统计、下一关推导
├─ data/                内容层：课程与素材数据
│  ├─ courses.ts        5 个阶段与全部关卡（阶段 1 已开放）
│  ├─ badges.ts         徽章定义
│  └─ avatars.ts        头像与图形密码图标
├─ store/               状态层：zustand + localStorage 持久化
│  ├─ childStore.ts     儿童档案与登录状态
│  ├─ progressStore.ts  星级、最佳成绩、连续天数、徽章
│  └─ selectors.ts      跨 store 的组合选择器
├─ hooks/               useTypingSession：键盘监听与实时统计
├─ types/               course.ts / typing.ts：全部领域类型
└─ utils/               cn.ts：Tailwind 类名合并
```

分层原则：**内容（data）→ 规则（engine）→ 状态（store）→ 展示（components/pages）**。
上层可以依赖下层，下层不知道上层的存在，因此引擎与规则可以独立测试与复用。

## 二、数据流

1. `data/courses.ts` 定义阶段与关卡（含练习题目、目标字符、达标速度）。
2. `engine/progress.ts` 依据进度计算每关状态（locked / unlocked / completed）。
3. 孩子点击地图节点 → 路由 `/lesson/:lessonId` → `TypingPage` 查关卡。
4. `TypingStage` 逐题驱动 `useTypingSession`，实时产出 WPM、正确率、弱键。
5. 一关结束 → `attemptAggregator` 汇总 → `progressStore.recordAttempt` 写入星级、连续天数与徽章。
6. `TypingResult` 展示结算，地图与首页立即反映最新进度。

## 三、如何增加课程内容（不改代码）

### 新增一个关卡

在 `src/data/courses.ts` 对应阶段的教案例表里追加一项即可，例如：

```ts
{
  title: '基准行连打',
  subtitle: 'asdf 与 jkl; 交替',
  kind: 'letters',
  focusChars: ['a', 's', 'd', 'f', 'j', 'k', 'l', ';'],
  targetWpm: 10,
  drills: [
    { text: 'asdf jkl; asdf jkl;', hint: '右手跟上左手的节奏。' },
    'fj fj dk dk',
  ],
}
```

新增关卡会自动出现在地图上、自动接入解锁规则与星级统计，无需改动任何组件。

### 开放一个新阶段

1. 把该阶段的 `available` 改为 `true`。
2. 用 `buildLockedLessons` 占位的关卡，替换为带 `drills` 的真实关卡（或直接写 `LessonSeed` 列表）。
3. 阶段配色、图标、进度条都会沿用现有组件自动生效。

### 内容校验建议

每关的 `focusChars` 应与 `drills` 中实际出现的字符一致，这是后续做"内容自动校验脚本"的钩子：可以在 CI 中检查字符覆盖率、题目长度、是否包含未开放阶段的字符。

## 四、如何增加新的关卡类型（代码关 / 游戏关）

当前 `LessonKind` 已预留 `symbols / code / game`。接入新类型时遵循同样的分层：

1. `types/course.ts`：如需要新的题目结构（代码题、游戏题），扩展 `DrillMode` 或新增题目类型。
2. `engine/`：新增对应的判定引擎（例如代码关的语法检查 + 运行断言），保持纯函数、可单测。
3. `components/`：新增展示组件（代码编辑器、运行结果面板）。
4. `pages/`：新增页面或在现有页面内按 `lesson.kind` 分派到不同的练习组件。

`TypingPage` 目前直接渲染 `TypingStage`，推荐未来改为按类型分派的容器：

```
lesson.kind === 'code' ? <CodeStage /> : <TypingStage />
```

这样打字关与代码关可以共享同一套进度、星级与结算体系。

## 五、后续接入后端时要改哪些地方

MVP 全部数据保存在浏览器本地（localStorage），后端接入时只需替换状态层的持久化实现：

| 现在 | 将来 |
|---|---|
| `childStore` 的 localStorage 档案 | 家长手机号认证 + 孩子档案接口 |
| `progressStore.recordAttempt` | 上报会话级聚合数据（不上传逐键明细） |
| `progressStore` 的星级与连续天数 | 服务端返回，支持多设备同步 |
| 本地徽章判定 | 服务端统一判定，避免多端不一致 |

组件与引擎无需改动，这是当前分层的直接收益。

## 七、MVP 边界（本阶段刻意不做）

- 课程只开放阶段 1（12 关），阶段 2-5 仅展示节点。
- 登录为本地档案 + 图形密码，未接家长手机号认证。
- 未实现代码编辑器、Python 运行沙箱、家长端报告页。
- 未接入云端数据与多设备同步。

## 八、游戏化体验层（2026-09 交互改版）

本次改版的目标是让孩子感觉「在玩游戏」，而不是「在用学习软件」。新增的分层：

```
src/
├─ engine/
│  ├─ sfx.ts          Web Audio 实时合成音效（无音频素材文件）
│  └─ rewards.ts      星星→能量(XP)、等级、连击里程碑的统一口径
├─ store/
│  └─ settingsStore.ts 声音开关等孩子偏好
├─ styles/
│  └─ kid.css         动效层（礼花、火花、星星弹出、进度流光、眨眼），并尊重系统「减少动态效果」
└─ components/
   ├─ mascot/Mascot.tsx    机器人伙伴小叮，五种表情替代文字提示
   ├─ fx/Confetti.tsx      过关礼花
   ├─ fx/Sparkles.tsx      敲对时迸出的小火花（最即时的奖励）
   └─ typing/LevelIntro.tsx 关卡开场倒计时
```

### 即时反馈的节奏

| 时刻 | 反馈 |
|---|---|
| 每敲对一个键 | 字符变绿 + 火花迸出 + 清脆短音（音高随机，避免机械感）+ 小叮开心 |
| 每敲错一次 | 柔和低沉音 + 角色歪头，字符轻轻晃动并停在原地（不用红叉、不扣分动画） |
| 连续敲对 ≥3 | 连击计数器出现，达到 5/10/20/30/50 时有跳动的夸奖语与琶音 |
| 每道题完成 | 「答对啦！」弹出 + 双音提示 |
| 每关结束 | 礼花 + 星星逐颗弹出（每颗配一声上行音）+ 能量条增长 + 可一键进入下一关 |
| 获得徽章 | 徽章弹出音与展示 |

### 挫败感控制

- 提示阶梯保留 L0→L4，第 5 次连续错误时提供「先跳到下一个键」，不让手指卡死。
- 结算页只展示「下次可以再练练」的中性建议，不出现错误次数、红叉或「失败」字样。
- 星级最低也是 1 星，文案始终是鼓励（「过关啦！」），再练一次随时可选。

### 无障碍与噪音控制

- 所有动效在 `prefers-reduced-motion: reduce` 下自动关闭。
- 顶部常驻声音开关，默认开启，可一键静音（课堂场景）。
- 训练进行中外层状态条会隐藏，减少干扰。

## 九、关卡解锁规则（2026-09 改版）

`src/engine/progress.ts` 中的解锁规则（最终版见第十章）：

1. **循序渐进**：第 1 关默认解锁，此后每关需要前一关至少 1 星。
2. **自由选择**：累计通过 5 关后，该阶段剩余关卡全部解锁，孩子可以自己决定先玩哪一关（地图上会弹出「解锁啦！剩下的关卡你说了算」并播放解锁音效）。

「下一关」按钮始终指向「最早未通关的已解锁关卡」，因此跳着玩也不会迷路。
规则由 `scripts/unlock-selftest.ts` 覆盖（18 项断言）。
## 十、2026-09 最终调整（第 5 轮）

### 解锁规则最终版（三层）

定义在 `src/engine/progress.ts`，两个常量控制全部行为：

| 常量 | 默认值 | 含义 |
|---|---|---|
| `FREE_START_LESSONS` | 3 | 每个岛的前 3 关直接开放，孩子可以任意顺序开始 |
| `FREE_CHOICE_AFTER` | 5 | 累计通过 5 关后，该阶段剩余关卡全部解锁 |

规则顺序：前 3 关自由 → 第 4 关起按顺序（前一关 ≥1 星）→ 通过 5 关后自由选择。
若想改成「全程按顺序」，把 `FREE_CHOICE_AFTER` 设成大于关卡总数即可；若想一开始就全开放，把 `FREE_START_LESSONS` 设成关卡总数。
两种情况的断言都写在 `scripts/unlock-selftest.ts`（20 项）。

- 键盘 `Escape` 也可以直接返回地图。

## 十八、2026-10 C++ 教学解释器（第 13 轮，第 1 步）

### 目标

让岛 4、岛 5 的代码关从「照抄打字」变成「写代码 → 真的运行 → 看结果」。

### 技术选择：为什么不直接用浏览器里的 clang

| 方案 | 体积/启动 | 能否逐行演示 | 结论 |
|---|---|---|---|
| clang / LLVM 编译成 WASM | 20-40MB，老笔记本启动要几秒 | 不能（只有编译结果） | 不用 |
| 现成的 JS 版 C++ 解释器 | 小 | 弱，报错是英文 | 不用 |
| **自己写教学子集解释器** | **几十 KB，毫秒级** | **可以，自带执行轨迹** | **采用** |

理由：我们 64 关教到的语法是有限的、明确的；自己实现换来秒级运行、完全中文的报错、以及"这一行执行时变量是几"的逐行演示能力——这是编译器给不了的。
架构上把运行层隔离在 `src/engine/cpp/`，将来若要换成真编译器，只需替换这一层。

### 结构

```
src/engine/cpp/
├─ ast.ts          语法树类型定义
├─ lexer.ts        词法分析 + 两类错误（语法/运行时，都带行号和提示）
├─ parser.ts       递归下降语法分析
├─ interpreter.ts  执行引擎（作用域、类型强制、沙箱保护、执行轨迹）
└─ index.ts        对外接口：runCpp(source, { input }) → { ok, output, error, trace, variables }
```

### 支持的语法（覆盖全部课程内容）

- 类型：`int` `double` `float` `bool` `char` `string`，`const` 前缀兼容
- 声明：`int x = 5;`、`int a = 1, b = 2;`、`int a[3];`、`int a[] = {1,2,3};`
- 运算：`+ - * / %`、`== != < > <= >=`、`&& || !`、`++ --`、`= += -= *= /= %=`
- 语句：`if/else`、`for`、`while`、`break`、`continue`、`return`、代码块、`//` 与 `/* */` 注释
- 输入输出：`cout << ... << endl;`、`cin >> x;`
- 函数：自定义函数（含参数与返回值）、`main()` 入口
- 宽容处理：`#include` 整行跳过、`using namespace std;` 跳过、`std::cout` 兼容
- 内置函数：`rand()` `abs()` `max()` `min()` `sqrt()` `pow()`

### 与真实 C++ 一致的地方

- 整数除法：`7 / 2` 得 `3`，`7 / 2.0` 得 `3.5`（靠表达式的"是否小数字面量/小数值变量"判断）
- 类型强制：`int n = 3.9;` → `3`；`bool` 打印成 `1`/`0`；`char c = 'A';`
- 数组下标从 0 开始，越界会报错

### 刻意做的孩子向调整

- 报错可以说人话：「还没有一个叫「score」的盒子，先用 int score = 0; 把它建出来」
- 少写分号时，行号指向**语句开始那一行**，而不是发现问题的下一行
- `cout << "score: " << score;` 支持文字与数字混排；`"a" + "b"` 允许拼接（真实 C++ 不允许）
- 直接打印整个数组会给出引导：「要一个一个打印，比如 cout << scores[0];」

### 沙箱保护

- 步数上限（默认 10 万）：拦住停不下来的循环，报「程序跑了太多步」
- 输出上限（默认 8000 字符）：拦住疯狂打印
- 递归深度上限：拦住无限递归
- 输入缺失：提示「运行前先把要输入的内容填进「输入」框」

### 为后续两步预留的能力

`runCpp` 返回 `trace: [{ line, outputLength, variables }]`——每一行执行完之后的变量快照，第 4 步的「逐行演示」直接回放这份轨迹即可，不需要再改引擎。

### 测试

`scripts/cpp-selftest.ts`：**64 项断言**，覆盖 8 个方面——能跑起来、变量与运算、判断与循环、数组与函数、输入交互（含完整猜数字游戏）、错误拦截、沙箱保护、执行轨迹。

## 二十一、2026-10 让游戏动起来（第 16 轮，第 4 步）

### 新增两个能力：wait（时间）与 key（按键）

| 函数 | 作用 |
|---|---|
| `wait(秒)` | 这一帧画完了，停一下（0 到 5 秒） |
| `key()` | 读一个按键（按的键写在输入框里，一行一个） |

配合已有的 `clear()`，孩子就能写出会动的画面：

```cpp
int ballY = 0;
for (int i = 0; i < 6; i++) {
  clear();               // 清掉上一帧
  ballY = ballY + 20;    // 往下掉一点
  circle(60, ballY, 10); // 画出这一帧
  wait(0.2);             // 停 0.2 秒再画下一帧
}
```

这就是"动画"最朴素的原理：**清屏 → 画新位置 → 停一下 → 再画**。

### 帧模型（为什么不用实时循环）

解释器是"先跑完、再回放"的模型：执行时把舞台指令连同 `wait` 一起记下来，界面再用 `resolveFrames()` 把它们切成帧，按每帧记录的时长逐帧播放。
好处：确定、可测试、可重播、有沙箱上限；坏处：动画是"录播"而不是"实时物理"。

`resolveFrames()` 的规则：
- 没有 `wait` → 只有一帧（一张静态画面）
- 每次 `wait` → 存一帧（含要停的秒数）
- `clear()` → 当前画布清空（下一帧从头画）
- 循环末尾如果是"清屏但没再画东西"，会补一帧空白，保证最后一帧和真实画面一致
- 画面判定看的是**最后一帧**，所以动画关卡也能自动判分

### 「写代码时间」的变化

- 运行完自动播放动画；面板下方有「▶ 重播动画」「⏩ 最后一帧」和「第 3 / 6 帧」计数。
- 没有 `wait` 的关卡会显示提示：「想让它动起来？试试 clear() 清屏 + wait(0.2) 停一下」。

## 二十四、2026-10 代码里的中文内容 + 打字界面不再跳动（第 19 轮）

### 一、代码里给屏幕看的内容改成中文

用户的反馈："某些需要输出的内容不要写英文，孩子比较小看不懂，比如猜数字的 win，就改成你猜对了"。

**技术上的矛盾**：孩子用英文键盘练习，**打不出中文字符**——把 `cout << "你猜对了";` 写进练习题，孩子就卡住了。

**解法**：给打字引擎加了「自动填好」能力。

- `isAutoChar(char)`：判断某个字符孩子能不能用英文键盘敲出来（中文、标点之外的 CJK 字符等）。

cout << "你好";        // 中文自动填好，孩子练的是 cout 和引号
cout << "赢啦";
text("太大了", 20, y);
string word = "小猫";

- 打字内容（8 关）：`cout << "hi"` → `"你好"`、`"win"` → `"赢啦"`/`"赢了"`、`"kid"` → `"大孩子"`、`"done"` → `"完成啦"`、`"my game"` → `"我的游戏"`、`"cat"` → `"小猫"`

## 二十五、2026-10 中文由孩子自己用拼音打（第 20 轮）

### 做法：内置一个"拼音输入法"

孩子在自己的键盘上敲拼音，屏幕给出提示和候选，确认后中文才落到代码里——这就是真实中文输入法的心智模型，只是把输入法做进了产品里，孩子不用切系统输入法。

## 二十六、2026-10 中文改成「一个字一个字打，打完立刻变绿」（第 21 轮）

## 三十五、2026-10 中文音效"没生效"的真正原因（第 30 轮）

上一轮加的音效其实没接错，是**打中文时每一次击键都被判成了"敲错"**，所以正确反馈那一支根本不会执行。

原因在 `src/hooks/useTypingSession.ts` 的击键处理里：

```ts
const expected = current.text[current.cursor]   // 中文时这是「你」
const isCorrect = expected === char             // 孩子按的是 n，永远不相等
```

中文的目标字符是汉字，孩子按的是拼音字母，这样比当然永远不相等。后果不只是没声音：

- 每敲一个拼音字母都放"敲错"的低音，正确音一次也不会响；
- 小山竹的表情一直显示"哎呀"；
- 下面的虚拟键盘每个字母都闪红框。

修法：

- `typingEngine.ts` 新增 `isKeystrokeCorrect(state, char)`：判定用 `getExpectedKey()`，中文按拼音字母比、中文标点按对应的英文键比。
- `useTypingSession.ts` 改用这个函数判定，删掉直接拿目标字比较的写法。
- 这样上一轮的 `hanzi()`（打出一个汉字的那声"叮"）才真正轮到它发言：字母是清脆的"嗒"，一个字打完换成两声小铃铛。

`engine-selftest` 补 4 条断言（拼音字母算对、按汉字算错、中文标点按逗号键算对、按中文逗号算错）。九套自测 **409 项断言**、类型检查、构建全部通过。

## 三十七、2026-10 中文音效真正的病根（第 32 轮）

现象：打第一个字正常，从第二个字开始，拼音每敲一个字母都响一次「叮」，铃声连成一片。

病根：判断"刚打出一个汉字"用的是**按键之后**的光标。

```ts
const landed = state.text[state.cursor - 1]   // 拼音中间的字母并不会移动光标
```

打第一个字时光标还在 0，前面没字，所以判断是对的；从第二个字起，光标停在"上一个字"后面不动，`text[cursor - 1]` 拿到的始终是**上一个汉字**，于是每一个拼音字母都被当成"又打出一个字"，铃声乱响。

实测（题目「你我他」，按键 n i w o t a）：

- 旧逻辑：静音 ding ding ding ding ding
- 新逻辑：静音 ding 静音 ding 静音 ding

修法：

- `typingEngine.ts` 新增 `strokeSound(state, char)`，返回 `chinese | pinyin | correct | wrong`：对错仍旧按拼音字母 / 中文标点判定，"字有没有落地"改成**比较按键前后光标有没有前进**，跟界面渲染时机彻底无关。
- `useTypingSession.ts` 在按键那一刻就把声音算好，挂在 `lastStroke.sound` 上；`TypingStage.tsx` 只负责照着放，不再自己读状态判断。
- `sfx.hanzi()` 从"两声铃"改成一声上扬的短铃（0.13 秒），下一个字的铃声不会跟它叠在一起。

`engine-selftest` 补 4 条断言，其中一条专门锁死这个坑：打「你我他」的声音序列必须是 `pinyin,chinese,pinyin,chinese,pinyin,chinese`。九套自测 **415 项断言**、类型检查、构建全部通过。

## 三十九、2026-10 打字时文字"浮动"：把会变的尺寸全部固定（第 34 轮）

打字过程中文字块会轻微浮动。排查到四处"尺寸/位置会变"的原因，全部固定住：

1. **当前字一直在呼吸**：`anim-breathe` + `scale-110` 让光标所在的字不停放大缩小，看着就是"浮动"。改成静态高亮（浅蓝底 + 4px 蓝环），位置完全不动，颜色变化仍有 150ms 过渡。
2. **空格字形会撑宽整行**：光标停在空格上时会把空白换成「␣」，宽度一变整行就重新折行、文字往上跳。改成固定宽度的盒子（`w-[0.62em]`），里面换什么字形宽度都不变。
3. **连击条到 3 才出现**：一出现就把下面的手指提示和键盘顶下去一截。改成一直占位、没到 3 时 `invisible`，×数字也给了固定最小宽度。
4. **速度数字位数变化**：0 → 12 → 100 的时候会把连击条挤到下一行。三个读数的数字改成固定最小宽度 + 右对齐（`tabular-nums`），宽度不再变。

## 四十四、2026-10 修掉"连击提示把文字框挤下去"（第 39 轮）

现象：每出现一次「不错哦！」这类连击鼓励，文字框就往下跳一下，六个岛都一样。

原因：那个提示是绝对定位的浮层（`absolute -top-3`），写在左栏的最前面，而左栏用的是 Tailwind 的 `space-y-3`：

```css
.space-y-3 > :not([hidden]) ~ :not([hidden]) { margin-top: .75rem }
```

平时文字框是左栏的第一个子元素，吃不到这条规则；提示一出现，文字框就变成「第二个子元素」，于是凭空多出 12px 上边距。提示消失又还原，连击频繁时就是一路往下跳。

修法：左栏不再用 `space-y-3`，改成给拼音条和统计条显式写 `mt-3`，间距固定下来，浮层出现与否都不影响布局。

顺带排查了其它几处「条件渲染 + space-y」的组合（CodeRunner 的舞台区、地图页、排行榜、输入法提示浮层），都是一次性加载或固定定位，不会在打字过程中跳动，未做改动。

改动已提交（`77eea8e`）、同步到 GitHub，并重新发布到 <https://bestgunners.github.io/codekids-keyboard-academy/>。
